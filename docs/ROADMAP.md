# 제품 로드맵

## 현재 MVP

현재 버전은 콘텐츠 캘린더, 운영 리스크, 증거 기반 분석, 다음 행동과 자동화 상태를 한 화면에 제공하는 운영 대시보드다. 성과는 화면에서 입력하고 CSV로 내려받을 수 있으며, 콘텐츠 원본은 JSON과 CSV로 관리해 특정 호스팅에 종속되지 않는다.

## 1단계 — 운영 기준선

첫 2~4주 동안 Instagram·Threads 게시물의 24시간, 72시간, 7일 성과를 기록한다. 도달, 저장, 공유, 프로필 방문, 링크 클릭, 확인 가능한 문의만 사용한다. 이 단계에서는 자동 게시보다 데이터 정의와 수집 습관을 먼저 고정한다.

## 2단계 — 승인과 협업

운영자가 브라우저에서 원고 상태를 바꾸고 승인 이유를 남길 필요가 생기면 정적 JSON을 API와 데이터베이스로 이전한다. 사용자 계정에는 최소 권한을 적용하고, 콘텐츠와 지표 이외의 개인정보는 저장하지 않는다. 기존 JSON 필드 이름을 API 계약으로 유지해 프런트엔드 변경을 줄인다.

## 3단계 — 공식 API 수집

Instagram·Threads 공식 API 권한을 확보한 뒤 게시물별 지표를 수집한다. 토큰은 서버 환경변수에만 저장하고 클라이언트에 노출하지 않는다. 자동 수집값은 원본 응답 시각과 출처를 함께 기록하며, 수동 수정값과 구분한다.

## 4단계 — 예약 발행

자동 발행은 최종 승인, 예약 취소, 실패 알림, 중복 방지 키가 준비된 뒤 도입한다. 자동 DM은 실제 계정에서 키워드 트리거와 응답 링크를 테스트하기 전에는 활성화하지 않는다. Threads와 Instagram의 문안을 동일하게 복사하지 않고 채널별 템플릿을 유지한다.

## 범용성

데이터 구조는 특정 지역, 직무 또는 캠페인명에 묶이지 않는다. `audience`, `platform`, `campaign`, `content_id`, `metric`을 분리하면 생산·현장직 외 다른 직무군과 추가 채널로 확장할 수 있다. Docker 이미지와 GitHub Actions는 어떤 호스팅에서도 같은 검증 절차를 재사용하도록 유지한다.
